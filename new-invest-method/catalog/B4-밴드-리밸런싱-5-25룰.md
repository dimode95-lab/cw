# B4. 밴드 리밸런싱 (5/25 Rule)

```yaml
name: 밴드 리밸런싱 (Larry Swedroe 5/25 Rule)

origin: >
  Larry Swedroe (Buckingham Strategic Wealth), Bogleheads 커뮤니티에서 표준 리밸런싱
  기법으로 널리 채택. 완전 공개.
  - https://www.bogleheads.org/wiki/Rebalancing
  - https://www.bogleheads.org/forum/viewtopic.php?t=185596
  - https://awealthofcommonsense.com/2014/03/larry-swedroe-525-rebalancing-rule/

category: B  # 목표가치·리밸런싱형

assets: >
  전략 자체는 자산 종류를 규정하지 않음 — 임의의 다중자산 포트폴리오(예: 주식/채권
  60/40, 혹은 국내주식/해외주식/채권/금 세분화)에 적용하는 "판정 알고리즘". 구현 시
  임의의 asset set 선택. lot_size는 정수 주 가정.

state: >
  자산별 current_weight (Decimal, 시가 기준 포트폴리오 내 비중). 목표비중은 params에
  고정값으로 보유하며 별도 상태변수 없음.

params: >
  target_weight(자산별 목표비중 dict), absolute_band=5%p(목표비중 ≥20%인 자산에 적용),
  relative_band=25%(목표비중 <20%인 자산에 적용, 예: 목표15%면 ±3.75%p), 원금.

schedule: >
  evaluation_frequency=일별 또는 정기 점검(월간 등, 구현자 선택 — 원 규칙은 판정
  주기를 규정하지 않음). trigger_condition=평가 시점에 한 자산이라도 밴드
  이탈 시에만 전체 리밸런싱 실행 (캘린더 리밸런싱이 아님 — "감시는 자주, 매매는
  드물게"가 핵심).

cycle_definition: >
  포지션 생애주기 개념 없음(영구 유지형). trigger=밴드 이탈 감지, resets=리밸런싱 후
  전 자산 비중을 target_weight로 재설정, carries=없음.

mode_transition: >
  상태기계 없음 — 단일 상태에서 매 평가 시점 밴드 이탈 여부만 이진 판정.

order_roles: >
  REBALANCE_BUY(비중 부족 자산 목표치까지 매수), REBALANCE_SELL(비중 초과 자산
  목표치까지 매도). 밴드를 이탈한 자산뿐 아니라, 이탈이 트리거되면 통상 전 자산을
  목표비중으로 동시 재조정(구현자가 "이탈 자산만" vs "전체 재조정" 택일 가능 — 원
  규칙은 후자를 전제).

fill_interaction_rules: >
  해당 없음 — role이 단순하고 동일일 체결 조합에 의존하는 비선형 상태갱신 로직 없음.

rounding: 정수 주 내림 외 특이사항 없음

rules: |
  # 평가 시점마다 실행
  triggered = False
  for asset in portfolio.assets:
      dev = current_weight[asset] - target_weight[asset]
      if target_weight[asset] >= 0.20:
          if abs(dev) > 0.05:               # 절대 5%p
              triggered = True
      else:
          if abs(dev) / target_weight[asset] > 0.25:   # 상대 25%
              triggered = True
  if triggered:
      for asset in portfolio.assets:
          rebalance_to(asset, target_weight[asset])   # 전 자산 목표비중 재조정

orders: >
  지정가/시장가는 구현자 선택 — 원 규칙은 체결가격 방식을 지정하지 않음. 백테스터
  기본값은 리밸런싱 판정일 종가 기준 매매.

fee_model: 매매수수료율 파라미터화. 세금은 프로젝트 공통 세금엔진(tax.py)로 별도 처리.

dividend_handling: >
  배당·이자는 현금으로 유입 후 다음 평가 시점에 비중 계산에 포함. 목표배분에 현금
  자산이 없으면 재투자 대기 buffer로만 취급(비중 왜곡 요인이므로 평가 시 반영).

cash_profile: >
  목표배분에 현금이 명시되지 않으면 상시 저비중. 현금을 별도 자산으로 포함하면
  일반 asset과 동일하게 밴드 판정 대상.

risk_notes: >
  밴드를 넓게 잡을수록 매매빈도·거래비용 감소하나 추적오차 확대, 좁힐수록 반대.
  급락장에서 주식 밴드 하단 이탈 시 자동으로 저가 매수(역발상 매매) 효과, 급등장
  에서는 이익실현 효과. 파산·강제손절 조건 없음(영구 리밸런싱).

automation: >
  밴드 판정 로직 자체는 규칙적이라 KIS API 자동화 난이도 낮음. 사람 개입 지점:
  자산군 구성 결정, 밴드폭(기본 5/25 외 변형) 채택 여부.

backtest_notes: >
  자산이 3개 이상일 때 각 자산을 목표비중 ≥20% / <20%로 사전 분류한 뒤 절대/상대
  밴드를 각각 적용해야 함. 평가 주기(일별 vs 월별)에 따라 매매빈도·결과가 달라지므로
  리포트에 채택한 평가 주기를 명시.
```
