## state

| 변수 | numeric_type | 설명 |
|---|---|---|
| V (목표가치) | Decimal 권장 | "TQQQ 평가금이 어떤 흐름으로 가야 할지" 가이드하는 목표선. 2주마다 공식으로 갱신 |
| Pool | Decimal | 보유 현금(예수금). 상승률 계산의 입력이자 밴드 이탈 매수의 재원 |
| 평가금(현재가치) | Decimal | 보유 TQQQ 수량 × 현재가. 밴드(V×0.85~V×1.15)와 비교되는 실측값 |
| 보유수량 | Int | TQQQ 보유 주수 |
| G (기울기) | 파라미터(정수, 상태 아님) | 10 또는 20. V 상승 기울기를 낮추는 정도 — 사실상 파라미터지만 상태처럼 사이클마다 재대입되진 않음 |
| 적립금 | Decimal, 사이클마다 외부 입력 | 적립식일 때만 존재하는 주기 투입액 |
| 인출금 | Decimal, 사이클마다 외부 입력 | 인출식일 때만 존재하는 주기 인출액 |

## schedule

- `evaluation_frequency`: **2주(격주)**. 매 사이클마다 V값을 공식으로 갱신하고 매수표·매도표를 다시 만든다.
- `trigger_condition`: **밴드 이탈**(평가금이 V×0.85 미만 또는 V×1.15 초과)일 때만 실제 매매가 발생.
  밴드 안에 있으면 해당 사이클은 무매매(관망)로 추정된다 — 원문이 "이 구간을 벗어나면 매수 또는 매도를
  해서 다시 밴드안으로 진입함"이라고 서술해, 밴드 내부 유지 시 매매 트리거가 없음을 함의.
  단, 원문에 "2주마다 V·매수표·매도표가 갱신된다"는 서술이 있어 **표는 2주마다 항상 갱신되지만,
  실제 체결(매수/매도)은 밴드 이탈이 확인되는 시점에만 발생**한다는 이중 구조로 해석함
  (evaluation_frequency=2주 + trigger_condition=밴드이탈, PLAN.md 스키마 지시대로 분리 기술).
- 일평가(daily) VR 변형(매일 밴드 체크)도 커뮤니티에 존재할 수 있으나, 본 원문은 2주 사이클만 규정.

## cycle_definition

무한매수법과 달리 VR은 "보유수량 0 → 종료" 식의 명확한 사이클 종결 개념이 원문에 없다
(장기 보유·리밸런싱형 전략이라 사이클이 "영구 반복되는 2주 평가 루프"에 가깝다).

| 항목 | 값 |
|---|---|
| trigger | 2주(격주) 경과 시 V 재계산 사이클 시작 |
| resets | 없음(V는 매 사이클 새 값으로 대체되지만 "리셋"이 아니라 "갱신") |
| carries | Pool, 보유수량, 누적 실현손익 모두 사이클을 넘어 계속 이어짐 |
| 실질 종료 | 사용자가 전략을 중단하기로 결정하는 시점(규칙상 강제 종료 조건 없음) |

## mode_transition

VR5.0 원문에는 무한매수법과 같은 명시적 상태기계(NORMAL/REVERSE 등)가 없다.
상태는 사실상 "밴드 안(관망)" / "밴드 상단 이탈(매도)" / "밴드 하단 이탈(매수)" 3구간으로 매
사이클 독립적으로 판정되며, 과거 사이클의 모드를 기억해 전이 조건을 따지는 구조가 아니다.

```yaml
states: [IN_BAND, ABOVE_BAND, BELOW_BAND]   # 상태라기보다 매 2주 평가 시점의 판정 결과
transitions:
  - from: "*"
    to: ABOVE_BAND
    condition: "평가금 > V * 1.15"
  - from: "*"
    to: BELOW_BAND
    condition: "평가금 < V * 0.85"
  - from: "*"
    to: IN_BAND
    condition: "V*0.85 <= 평가금 <= V*1.15"
# ABOVE_BAND -> 매도, BELOW_BAND -> 매수, IN_BAND -> 무매매
```

## order_roles

무한매수법처럼 세분화된 role 태그가 원문에 없다. 백테스트/구현 시 아래 2개 role로 단순화 가능.

| role(제안) | 발생 조건 | 방향 |
|---|---|---|
| `BAND_UPPER_SELL` | 평가금 > V×1.15 | SELL — 밴드 안으로 복귀시킬 만큼 매도, Pool 증가 |
| `BAND_LOWER_BUY` | 평가금 < V×0.85 | BUY — Pool에서 밴드 안으로 복귀시킬 만큼 매수, Pool 감소(한도 내) |

## fill_interaction_rules

무한매수법과 같은 "같은 날 여러 role 조합에 따른 비선형 상태갱신"은 원문에 없음(2주 1회 평가·1회
매매가 원칙). 체결 후 상태갱신은 다음과 같이 단순:

| 이벤트 | 상태 갱신 |
|---|---|
| 매도 체결 | Pool += 매도대금(-수수료), 보유수량 -= 매도수량 |
| 매수 체결 | Pool -= 매수원가(+수수료), 보유수량 += 매수수량, Pool 사용은 한도(적립75%/거치50%/인출25%) 이내로 제한 |
| 사이클 종료 시(2주 경과) | V 재계산 → 다음 사이클로 이월 |

## rounding

| 항목 | 계산식 | 모드 | 자릿수 |
|---|---|---|---|
| 다음 V | 현재V + Pool/G + 적립금(또는 - 인출금) | 원문에 반올림 규칙 명시 없음. 예시(9000+100+250=9350)는 정수 단위라 반올림 이슈가 드러나지 않음 | **미확정 — 구현 시 가정 필요**(제안: 센트 HALF_UP, 무매수법과 일관성 유지) |
| 밴드 경계 | V×0.85, V×1.15 | 미확정 | 미확정 — 제안: 센트 HALF_UP |
| 밴드 이탈 시 매수/매도 수량 | (목표 복귀지점 − 평가금) / 현재가 | **미확정 — 구현 시 가정 필요**. "목표 복귀지점"이 V인지 밴드 경계(V×0.85 또는 V×1.15)인지 원문·공개자료로 확정 못함 | 수량은 정수 내림(DOWN) 가정 |
| Pool 사용 한도 적용 | 계산된 매수금액을 한도(75%/50%/25%)와 min() | 미확정 | 미확정 |

## rules (의사코드 — 원문 확정 부분 + 미확정 가정 명시)

```
# 2주(격주)마다 실행
function newCycle(state, poolPrevCycle, contribution_or_withdrawal, G):
    # 확정: V 갱신 공식 (원문 예시로 검증됨: V=9000, Pool=1000, G=10, 적립금=250
    #        -> 다음V = 9000 + 1000/10 + 250 = 9350)
    state.V = state.V + poolPrevCycle / G + contribution_or_withdrawal
    # contribution_or_withdrawal: 적립식=+적립금, 인출식=-인출금, 거치식=0

    band_lower = state.V * 0.85   # ±15% 기본, 10%/5% 대안 가능(원문)
    band_upper = state.V * 1.15

    currentValue = state.quantity * currentPrice
    poolLimit = poolUsageLimit(mode)   # 적립75% / 거치50% / 인출25% (사이클당 매수 재원 상한)

    if currentValue > band_upper:
        # ABOVE_BAND: 매도
        # 미확정: 목표 복귀지점 = V(가정 A, Value Averaging 원조 방식과 일치) 또는
        #          band_upper(가정 B, "밴드 안으로 복귀"라는 원문 문구와 더 직접 부합)
        target = state.V              # <- 가정 A. 구현 시 선택 필요, 두 방식 모두 백테스트 권장
        sellValue = currentValue - target
        sellQty = floor(sellValue / currentPrice)
        emit SELL role=BAND_UPPER_SELL qty=sellQty
        state.pool += sellValue  # 체결 후 실제 대금으로 갱신

    elif currentValue < band_lower:
        # BELOW_BAND: 매수
        target = state.V              # <- 가정 A (위와 동일 쟁점)
        buyValue = min(target - currentValue, state.pool * poolLimit)
        buyQty = floor(buyValue / currentPrice)
        emit BUY role=BAND_LOWER_BUY qty=buyQty
        state.pool -= buyValue

    else:
        pass  # IN_BAND: 무매매

function poolUsageLimit(mode):
    return { ACCUMULATION: 0.75, LUMP_SUM: 0.50, WITHDRAWAL: 0.25 }[mode]
    # 원문: "이후 사용제한을 점차 낮춰가기" — 낮추는 속도·트리거 조건 미확정
```

## orders

원문에 무한매수법과 같은 LOC/MOC 지정 없음. VR은 "2주 1회 리밸런싱형"이라 무한매수법만큼 매일
정밀한 호가 전략이 필요하지 않을 가능성이 높음.

| 상황 | 추정 유형 | 비고 |
|---|---|---|
| 밴드 상단 이탈 매도 | 지정가 또는 시장가(미확정) | 원문에 주문 유형 명시 없음 |
| 밴드 하단 이탈 매수 | 지정가 또는 시장가(미확정) | 원문에 주문 유형 명시 없음 |

**미확정 — 구현 시 가정 필요**: 주문 유형은 백테스트에서는 편의상 평가일 종가 체결로 가정
(MOC 또는 당일 종가 기준 지정가와 동일 취급) 권장.

## fee_model

원문에 수수료 언급 없음. 무한매수법과 동일한 파라미터화된 요율 가정을 재사용 권장(백테스트 일관성).

## dividend_handling

원문 언급 없음. TQQQ 기준이므로 A1과 동일하게 배당 영향 미미로 간주, 별도 현금흐름으로만 가산.

## cash_profile

- Pool(예수금)이 전략의 1급 상태변수 — 무한매수법의 "잔금"과 달리 V 공식 자체의 입력으로 쓰인다
  (Pool이 클수록 다음 V가 더 가파르게 상승 — "현금 비중이 많을수록 V값이 가파르게 상승" 서술과 부합).
- 평균 현금비중 실측치(원문 인용): 10년 백테스트에서 "P/V 평균 0.152 = 현금비중 13.2%".
- 한 사이클당 매수에 쓸 수 있는 Pool 비율에 상한(75%/50%/25%)을 둬 전액 소진을 방지 — 무한매수법에
  없는 VR 고유의 안전장치.

## risk_notes

- 원문 인용 리스크 지표: TQQQ를 "수익률 3배·위험도 3배", QLD를 "수익률 2배·위험도 2배" 레버리지로
  놓았을 때, VR은 "수익률 2.98배, 위험도 2.37배" — 즉 TQQQ와 거의 같은 수익률을 내면서 위험도는
  QLD(2배 레버리지)에 더 가깝게 낮춘다는 것이 원문이 주장하는 핵심 가치.
- 강제 손절·파산 조건 원문에 없음. 하락장에서도 밴드 하단 이탈 시 지속 매수하는 구조라 무한매수법의
  리버스모드와 유사한 "하락 중 매수 지속" 리스크가 있음 — 단 Pool 사용 한도(25~75%)가 손절 없는
  완충장치 역할.
- G값이 클수록 V 상승이 완만해져 상단 밴드 이탈(매도)이 잦아지는 방향으로 작동할 가능성 있음(원문
  서술로 미루어 추정, 수식 시뮬레이션 필요) — **미확정, 백테스트로 확인 필요**.

|---|---|

## backtest_notes

- 원문 인용 성과 지표(2010년대~ 10년 구간 추정, 정확한 기간 원문에 명시 안 됨): VR 수익률 2.98배

1. **밴드 이탈 시 매수/매도 후 정확한 목표 복귀지점** — V값 자체인지, 밴드 경계(V×0.85 /

   구현 시 두 방식 모두 백테스트해 결과 민감도를 확인할 것을 권장.
2. **V·밴드 계산의 반올림 규칙(자릿수/HALF_UP·DOWN)** — 원문에 명시 없음. 무한매수법과 일관되게
