## state

전략의 상태변수는 `StrategyState`(Models.kt) 스냅샷 하나로 표현된다.

| 변수 | numeric_type | 설명 |
|---|---|---|
| `tValue` (T) | **Double, 무반올림** | 진행회차. 소수점 자릿수 제한 없음(예: 9.890625). 정수 아님에 유의 |
| `avgPrice` (평단) | BigDecimal | 보유 평균단가. 매수/매도 체결마다 재계산 |
| `quantity` (보유수량) | Int | 보유 주식 수 |
| `cashBalance` (잔금) | BigDecimal | 사이클 내 남은 투자가능 현금(원금 기준, 외부자금 추가 없음) |
| `mode` | enum {NORMAL, REVERSE} | 일반모드 / 리버스(소진후)모드 |
| `divisions` (n) | Int | 분할수, 파라미터이자 상태의 분모 |
| `principal` | BigDecimal | 시작 원금 (참고값, 계산에 직접 쓰이진 않음 — cashBalance가 실사용) |

**주의**: T는 상태변수이자 반올림 없는 실수(Double)로 유지된다. 반면 금액(잔금·평단·주문가)은 전부
BigDecimal. 이 이원화(T=Double, 금액=BigDecimal)는 실구현의 핵심 설계이며, 파이썬 이식 시
"T는 float 그대로, 금액은 Decimal"로 그대로 재현해야 오차가 나지 않는다 (PLAN.md 4.2 참조).

## schedule

- `evaluation_frequency`: **매일 (거래일 기준)**. 매일 종가 마감 후(또는 프리장 시작 전) 당일 보유·평단·T로 다음날 주문표를 재계산한다.
- `trigger_condition`: 상시 — 매일 LOC/LOC/지정가 주문을 새로 건다 (전일 미체결분은 자동 취소되고 재계산된 가격으로 갱신, 주간장 미이용).
- 지정가 매도만 예외적으로 "프리장 시작 시각(서머타임 저녁5시/비서머타임 저녁6시, 한국시각)"에 걸어 프리장~본장~애프터장까지 유효기간을 최대로 활용할 것을 권장 (원문 §6).
- 리버스모드 진입/이탈 판정도 매일 체크한다.
- 실구현 `MorningSyncWorker`는 이 스케줄과 별개로 "체결 자동 인식"을 위해 매일 08:20(KST) 이후 폴링하는 별도 잡(주문표 생성 자체와는 무관, 체결 반영용).

## cycle_definition

| 항목 | 값 |
|---|---|
| trigger (사이클 시작) | `quantity == 0` 인 상태에서 새로 진입 (T=0, 잔금=원금 또는 원금+누적수익) |
| trigger (사이클 종료) | 체결 반영 후 `quantity == 0` (전량 매도 완료) → `cycleClosed = true` |
| resets | 사이클 종료 시 `tValue = 0.0`, `mode = NORMAL` 로 리셋. `cashBalance`는 리셋하지 않고 매도 대금이 누적된 값을 그대로 다음 사이클 잔금으로 이어감(복리). 단리 운용을 원하면 사용자가 수동으로 잔금을 원금으로 재설정 (원문 §7-(3): 복리/단리는 선택) |
| carries | 실현손익 로그(`cycle_log`)는 사이클과 독립적으로 계속 누적 기록됨 (앱의 수익일지 탭) |
| 재개 조건 | 지정가매도 체결 후 크게 하락해 LOC 매수가 다시 걸리는 경우 → 종료 아님, 그대로 이어서 진행 (원문 §7-(2)) — 구현상 이 경우는 `quantity > 0`으로 유지되어 자동으로 사이클이 계속됨 |

## mode_transition

상태기계: `NORMAL ⇄ REVERSE`

```yaml
states: [NORMAL, REVERSE]
transitions:
  - from: NORMAL
    to: REVERSE
    condition: "quantity > 0 AND isExhausted"
      # isExhausted := tValue > divisions - 1.0  (1회분 미만 잔여 = 소진)
      # 원문: 20분할은 T>19, 40분할은 T>39부터 (즉 T > n-1). 잔금이 남아있어도 강제 전환.
  - from: REVERSE
    to: NORMAL
    condition: "close < avgPrice * (1 - targetRate)"
      # 종가가 평단 대비 -R(TQQQ -15%, SOXL -20%)보다 더 하락 확인된 날 즉시 복귀.
      # 단 하루만에 리버스가 끝나는 경우도 있음(원문 §6-(2)).
      # T값은 리버스에서 쓰던 값을 그대로 이어받아 NORMAL에서 계속 사용(리셋 안 함).
```

- `shouldEnterReverse` / `shouldExitReverse`는 매일 별도로 평가되는 순수 판정 함수이며,
  실제 모드 전환은 그날 주문 생성 전에 반영해야 한다 (판정 후 당일 주문표부터 반대 모드 로직 적용).
- 리버스모드 동안은 진입 이후 지속적으로 "종가 < 평단"인 것이 전제(손절 국면) — 원문 §6-(3).

## order_roles

`OrderRole` enum과 역할별 의미:

| role | 모드 | 발생 조건 | 가격결정 | T 갱신(체결 시) |
|---|---|---|---|---|
| `FIRST_BUY` | NORMAL, 사이클 첫날(qty=0) | 무조건 1회 매수 | 전일종가×(1+bigNumberRate), LOC | +1.0 |
| `STAR_HALF_BUY` | NORMAL 전반전(T<n/2) | 1회매수금의 절반 | 별지점−0.01(매수점), LOC | 단독 체결 시 +0.5 |
| `AVG_HALF_BUY` | NORMAL 전반전 | 1회매수금의 나머지 절반 | 평단가(그대로), LOC | 단독 체결 시 +0.5 |
| `FULL_STAR_BUY` | NORMAL 후반전(T≥n/2) | 1회매수금 전체 | 별지점−0.01, LOC | +1.0 |
| `LADDER_BUY` | 공통 | 폭락 대비, 위 매수가 아래로 1주씩 추가 (최대 12단) | budget/(누적수량+k), 2자리 HALF_UP | 없음(같은 날 본 매수 role과 동시 집계되므로 중복 가산 방지) |
| `QUARTER_SELL` | NORMAL 공통(전·후반) | 보유수량의 1/4 (내림) | 별지점(그대로), **LOC** | ×0.75 |
| `FINAL_SELL` | NORMAL 공통 | 나머지 3/4 | 평단×(1+R), 내림, **지정가(LIMIT)** | ×0.25 (다른 매수와 겹치면 그 매수분 가산 후) |
| `REVERSE_FIRST_SELL` | REVERSE 첫날 | 보유수량을 (n/2)등분(내림, 최소1주), 무조건 매도 | 가격 없음, **MOC** | ×(1−2/n) |
| `REVERSE_SELL` | REVERSE 둘째날~ | 직전 보유수량을 (n/2)등분(내림, 최소1주) | 직전5거래일 종가평균, LOC | ×(1−2/n) |
| `REVERSE_BUY` | REVERSE 둘째날~ | 잔금/4 (쿼터매수) | 리버스별지점−0.01, LOC | += (n−T)×0.25 |

주문 유형 요약: 매수는 항상 **LOC**(리버스 첫날 매도 제외), 매도는 평시 쿼터매도=LOC·최종매도=지정가,
리버스모드 매도는 첫날=MOC·이후=LOC. 주간장(정규장外 애프터 별도 세션)은 사용하지 않는다.

### 큰수매수 조정 (order role과 별개의 후처리)

`capBuysAtBigNumber`: 생성된 모든 LOC 매수 주문 중, 가격이 `전일종가×(1+bigNumberRate)`(=큰수 상한)를
초과하면 그 상한가로 **가격만** 낮춰서 건다(수량은 원래 계산값 유지). LOC이므로 실제 체결가는 종가로
결정되어 방법론상 의도("별가격 아래에서 무조건 매수")와 최종 결과는 동일 — 증권사의 가격범위 초과 주문
거부를 회피하기 위한 실무적 보정이다. 매도 주문에는 적용하지 않는다(원문: 매도거부는 그대로 둔다).

## fill_interaction_rules

같은 날 여러 role이 동시 체결되는 조합에 따라 T 갱신 규칙이 달라진다 (`applyFills` 순서: **매도 먼저 반영 → 매수 반영**).

| 체결 조합(같은 날) | T 갱신 | 비고 |
|---|---|---|
| `STAR_HALF_BUY` + `AVG_HALF_BUY` 둘 다 체결 | T += 1.0 | 절반씩 두 곳 모두 채워짐 = 1회 매수 완료 |
| `STAR_HALF_BUY` 만 체결 | T += 0.5 | |
| `AVG_HALF_BUY` 만 체결 | T += 0.5 | |
| `FIRST_BUY` 또는 `FULL_STAR_BUY` 체결 | T += 1.0 | 후반전/첫매수는 절반 분리가 없으므로 전량 매수 |
| `QUARTER_SELL` 체결 | T ×= 0.75 | |
| `FINAL_SELL` 체결, 같은 날 매수 없음 | T ×= 0.25, 보유 0 → **사이클 종료**(T는 0으로 리셋) | |
| `FINAL_SELL` 체결 + 같은 날 `STAR_HALF_BUY`/`AVG_HALF_BUY` 체결 (지정가매도 후 폭락으로 LOC매수까지 겹침) | T = (직전T × 0.25) + (매수분 가산: 둘다=+1.0 / 하나만=+0.5) | 원문 §2-(4) "(×0.25+1) or (×0.25+0.5)". 사이클은 종료되지 않고 계속됨(보유수량>0) |
| `REVERSE_FIRST_SELL` 또는 `REVERSE_SELL` 체결 | T ×= (1 − 2/n) | 20분할=×0.9, 40분할=×0.95, 30분할=×(1−2/30)≈×0.9333 |
| `REVERSE_BUY` 체결 | T += (n − T) × 0.25 | 쿼터매수. 매도와 같은 날 겹치면 매도 T갱신을 먼저 적용한 뒤 이 식의 T를 사용(구현은 매도 처리 후의 t로 계산) |
| `LADDER_BUY` 단독/동반 체결 | 추가 가산 없음 | 사다리는 항상 본 매수 role(STAR_HALF/AVG_HALF/FULL_STAR/FIRST/REVERSE_BUY)과 "동일한 예산"에서 나온 여분이라, 실제로는 그 role의 수량에 합산되어 함께 집계되는 관계 — role 자체의 T가산 규칙이 없다 |

체결 반영 시 잔금·평단 계산 순서(구현 그대로):
1. 매도 체결 전건 처리: `실현손익 += (체결가−직전평단)×수량 − 수수료`, `잔금 += 매도대금 − 수수료`, `보유수량 -= 수량`
2. 매수 체결 전건 처리: `잔금 -= 매수원가 + 수수료`, `보유수량 += 수량`
3. 신규 평단 = (매도 반영 후 원가합 + 매수 원가합) / 최종보유수량, 센트 HALF_UP
4. 위 표에 따라 T 갱신 (매도로 인한 변화 → 매수로 인한 변화 순서로 적용)
5. `quantity == 0`이면 사이클 종료 처리(T=0, mode=NORMAL)

## rounding

| 항목 | 계산식 | 모드 | 자릿수 |
|---|---|---|---|
| 별% (starPercent) | R×(1 − 2T/n) | 반올림 없음 (Double 그대로 유지) | — |
| 별지점(매도가, starSellPrice) | 평단×(1+별%) | **HALF_UP** | 2 (센트) |
| 별지점(매수가, starBuyPrice) | 별지점(매도가) − 0.01 | 상위 결과에서 단순 차감 (추가 반올림 없음) | 2 |
| 1회매수금(oneTimeBudget) | 잔금/(n−T) | Double MathContext.DECIMAL64로 나눗셈, 최종 사용 시점(가격 계산)에서만 센트화 | 자체는 미절사, 소비처에서 2자리화 |
| 최종 지정가 매도가(finalSellPrice) | 평단×(1+R) | **DOWN(내림)** | 2 |
| 리버스 별지점(reverseStarPrice) | 직전5거래일 종가 평균 | **HALF_UP** | 2 |
| 사다리 단가(ladder) | budget/(누적수량+k), k=1..12 | **HALF_UP** | 2 |
| 큰수 상한(capBuysAtBigNumber) | 전일종가×(1+bigNumberRate) | **HALF_UP** | 2 |
| 매수/매도 수량(floorDiv) | 예산 ÷ 가격 | **DOWN(내림)**, 정수화(scale 0) | 0 |
| 쿼터매도 수량 | 보유수량 / 4 | 정수 나눗셈(내림) | 0 |
| 리버스 매도 수량 | 직전보유수량 / (n/2) | 내림, 단 **결과 0이면 최소 1주로 보정** | 0 |
| 평단(신규 평단가) | 총원가/보유수량 | **HALF_UP** | 2 |
| 내부 연산 정밀도 | Double 곱셈에 `BigDecimal(double, MathContext.DECIMAL64)` 사용 | HALF_UP(BigDecimal 생성 규칙) | DECIMAL64(16유효자리) |

**중요**: 원문(자연어)은 "반올림", "내림" 두 단어만 등장하지만, 실구현은 계산 항목별로 HALF_UP과 DOWN을
엄격히 구분해 사용한다. 파이썬 이식 시 이 표를 그대로 따라야 MumaeEngine 픽스처 23개와 센트 단위까지 일치한다.

## rules (의사코드)

```
# 매일 1회, 장 마감 후(또는 프리장 개시 전) 실행
function buildOrders(state, prevClose, last5Closes, reverseFirstDay):
    if state.mode == NORMAL:
        orders = buildNormalOrders(state, prevClose)
    else:  # REVERSE
        orders = buildReverseOrders(state, prevClose, last5Closes, reverseFirstDay)
    return capBuysAtBigNumber(orders, state, prevClose)  # 큰수 조정 (매수만)

function buildNormalOrders(state, prevClose):
    budget = state.cashBalance / (state.divisions - state.tValue)   # 1회매수금
    if state.quantity == 0:
        bigNum = prevClose * (1 + state.bigNumberRate)  -> cents(HALF_UP)
        qty = floor(budget / bigNum)
        emit BUY LOC FIRST_BUY @ bigNum qty=qty
        emit ladder(budget, qty, LADDER_BUY)
        return  # 첫매수 날은 매도 없음(보유 0)

    starBuy = starSellPrice(state) - 0.01
    if state.tValue < state.divisions / 2:            # 전반전
        half = budget / 2
        starQty = floor(half / starBuy)
        emit BUY LOC STAR_HALF_BUY @ starBuy qty=starQty
        remaining = budget - starBuy*starQty
        avgQty = floor(remaining / state.avgPrice)
        emit BUY LOC AVG_HALF_BUY @ state.avgPrice qty=avgQty
        emit ladder(budget, starQty+avgQty, LADDER_BUY)
    else:                                              # 후반전
        qty = floor(budget / starBuy)
        emit BUY LOC FULL_STAR_BUY @ starBuy qty=qty
        emit ladder(budget, qty, LADDER_BUY)

    # 매도 (전·후반 공통)
    quarterQty = floor(state.quantity / 4)
    emit SELL LOC QUARTER_SELL @ starSellPrice(state) qty=quarterQty
    restQty = state.quantity - quarterQty
    emit SELL LIMIT FINAL_SELL @ finalSellPrice(state) qty=restQty   # 평단×(1+R), DOWN

function buildReverseOrders(state, prevClose, last5Closes, firstDay):
    sellQty = max(1, floor(state.quantity / (state.divisions/2))) if state.quantity>0 else 0
    if firstDay:
        emit SELL MOC REVERSE_FIRST_SELL qty=sellQty     # 가격 없음, 무조건 매도
        return   # 첫날은 매수 없음

    star = reverseStarPrice(last5Closes)                  # 직전5일 종가 평균, HALF_UP 2자리
    emit SELL LOC REVERSE_SELL @ star qty=sellQty
    quarterBudget = state.cashBalance / 4
    buyPrice = star - 0.01
    qty = floor(quarterBudget / buyPrice)
    emit BUY LOC REVERSE_BUY @ buyPrice qty=qty
    emit ladder(quarterBudget, qty, LADDER_BUY)

function ladder(budget, alreadyQty, role, maxRungs=12, minPrice=1.00):
    if alreadyQty <= 0: return []
    q = alreadyQty
    for i in 1..maxRungs:
        q += 1
        price = round(budget / q, 2, HALF_UP)
        if price < minPrice: break
        emit BUY LOC role @ price qty=1
    return

function capBuysAtBigNumber(orders, state, prevClose):
    cap = round(prevClose * (1+state.bigNumberRate), 2, HALF_UP)
    for o in orders:
        if o.side==BUY and o.type==LOC and o.price > cap:
            o.price = cap   # 수량은 유지, 라벨만 "(큰수 조정)" 부기

# ---- 체결 반영 (매일 체결 폴링 후 1회) ----
function applyFills(state, fills):
    cash, qty, totalCost = state.cashBalance, state.quantity, state.avgPrice*state.quantity
    realized = 0
    for f in fills.SELL_first:
        realized += (f.price - state.avgPrice)*f.qty - f.fee
        cash += f.price*f.qty - f.fee
        qty -= f.qty
        totalCost -= state.avgPrice*f.qty
    for f in fills.BUY:
        cash -= f.price*f.qty + f.fee
        qty += f.qty
        totalCost += f.price*f.qty
    newAvg = round(totalCost/qty, 2, HALF_UP) if qty>0 else 0

    t = state.tValue; n = state.divisions
    if any(sell.role==QUARTER_SELL): t *= 0.75
    if any(sell.role in {REVERSE_FIRST_SELL, REVERSE_SELL}): t *= (1 - 2/n)
    finalSold = any(sell.role==FINAL_SELL)
    if finalSold: t *= 0.25
    starHalf = any(buy.role==STAR_HALF_BUY); avgHalf = any(buy.role==AVG_HALF_BUY)
    fullBuy  = any(buy.role in {FIRST_BUY, FULL_STAR_BUY})
    if fullBuy: t += 1.0
    elif starHalf and avgHalf: t += 1.0
    elif starHalf or avgHalf: t += 0.5
    if any(buy.role==REVERSE_BUY): t += (n - t) * 0.25

    cycleClosed = (qty == 0)
    newState = state.copy(cashBalance=round(cash,2), avgPrice=newAvg, quantity=qty,
                           tValue = 0.0 if cycleClosed else t,
                           mode = NORMAL if cycleClosed else state.mode)
    return newState, round(realized,2), cycleClosed

# ---- 모드 전환 판정 (매일) ----
function shouldEnterReverse(state):
    return state.mode==NORMAL and state.quantity>0 and state.tValue > state.divisions - 1.0

function shouldExitReverse(state, close):
    if state.mode != REVERSE or state.avgPrice==0: return false
    return close < state.avgPrice * (1 - state.targetRate)
```

## fee_model

- 파라미터화된 요율(`feeRate`)로 추정: 매수는 잔금에서 추가 차감, 매도는 실현손익·수령액에서 차감.
- 실계좌 반영 시(실구현): 간편입력(문자 파싱)은 체결통보 문자의 실제 제비용을 사용, 자동인식(폴링)은 전략별 `feeRate` 추정치를 사용 — 두 값이 다를 수 있음(실측 vs 추정).
- 백테스트에서는 단일 `feeRate` 파라미터(예: 0.1~0.2% 또는 브로커 실측 평균)로 통일 권장.

## dividend_handling

- TQQQ/SOXL은 레버리지 ETF로 배당이 극히 낮거나 비정기적. 원문·구현 모두 배당 처리 로직 없음.
- 백테스트 시 PLAN.md 방침에 따라 원종가(raw close) 기준 체결가 계산 + 배당은 별도 현금흐름으로 가산(있다면). 무매 전략 자체는 배당을 재투자 로직에 포함하지 않음(잔금과 분리해 별도 누적 가정).

## cash_profile

- 사이클 진행 중 잔금은 T가 커질수록(1회매수금=잔금/(n−T)) 점점 얇게 쓰인다 — 후반으로 갈수록 회당 매수금은 커지는 경향(분모가 작아짐).
- 사이클 종료 시 잔금은 이론상 0에 가깝게 소진되어야 정상(전량 매도 후 잔여 현금 = 누적 수익 포함).
- 외부자금 추가 투입 금지(리버스모드 중에도) — 원문 §7. 정해진 원금(및 복리 시 누적 수익)만으로 운용.
- 리버스모드 중에도 잔금이 계속 재순환(매도금+기존 잔금)되며 4등분 쿼터매수로 소비됨.

## risk_notes

- 3배 레버리지 상품(TQQQ/SOXL) 기반이라 변동성이 매우 크다 — 원문은 초심자에게 TQQQ 우선 권장.
- 리버스모드는 정의상 "종가<평단"인 손절 국면의 연속 — 지속적 손절 매도가 전제되며, 이를 감내 못하면 방법론 이탈(개인 변형)로 간주됨(원문 §7 "기타").
- 파산 조건(명시적 강제 손절 없음): 극단적 장기 우하향 시 리버스모드가 장기화되며 원금 잠식이 지속될 수 있음 — 원문·구현 모두 이론상 종료 조건(-R 이탈 후 복귀) 외의 강제 손절선은 없음.
- 큰수매수는 방법론 자체가 아니라 "증권사 주문 거부 회피"용 실무 보정 — 원문이 명시(§8 도입부: "무한매수법 방법론과는 상관 없지만").
- 갭상승/갭하락이 큰 날은 고정 10% 큰수로는 부족/과다할 수 있어 사용자 재량 조정이 필요(원문 §2-2) — 이 부분은 구현이 완전 자동화하지 못한 "사람 판단 개입 지점"이다.

## backtest_notes

- **체결 가정**: LOC 매수는 `close ≤ limit`이면 종가로 체결, LOC 매도는 `close ≥ limit`이면 종가로 체결, MOC는 무조건 종가 체결, 지정가(최종매도)는 정규장 고저 범위로 판정(부분체결 미모델링) — PLAN.md 4.1 `broker_sim.py` 방침과 일치.
- **프리마켓 미반영 편향**: 실전은 지정가 최종매도를 프리장부터 걸어두지만 백테스터는 정규장 데이터만 사용 가능 → 매도가 실제보다 지연되는 방향의 편향 발생. 리포트에 명시 필요.
- **교차검증**: `MumaeEngineTest.kt`의 23개 테스트 케이스(별%/별지점/최종매도가/사다리/1회매수금/리버스별지점/applyFills 각 T조합)를 JSON 픽스처로 그대로 이식해, Python 구현이 센트 단위까지 일치하는지 검증해야 함(PLAN.md 4.4). 아래는 핵심 값 예시(전부 상태: n=30, R=15%, T=9.890625, 평단=76.12, 잔금=1062.17×(30-9.890625)):

  - 전반전 주문: 별지점 6주@80.00, 평단 7주@76.12, 사다리 75.87/70.81/66.39/62.48/59.01/55.90

## 미확정/가정 필요

- 없음. 규칙 원문과 실구현(단위테스트 포함)이 상호 검증되어 전 필드가 구현 기준으로 확정됨.
- 단, 원문 자체가 사용자 재량을 명시한 부분(큰수 %의 정확한 값, 갭상황 대응)은 "구현은 고정 파라미터로 근사, 실전은 사람 판단"이라는 점을 위 표에 명시해 둠 — 이는 "미확정"이 아니라 "원문이 의도적으로 가변적으로 남겨둔 지점"이다.
