# new-invest-method — 규칙 기반 투자 방법론 수집·정형화·백테스트 프로젝트

> 작성: 2026-07-17 (페이블 계획 단계)
> 파이프라인: **페이블계획 → 솔검증 → 토론 → 페이블오케스트 → 솔구현**

## 1. 배경과 목표

현재 라오어 무한매수법 V4.0을 MumaeApp(안드로이드 + KIS API)으로 실운용 중이다.
무한매수법·밸류리밸런싱(VR)이 매력적인 이유는 **"주가 등락에 일희일비하지 않고,
사전에 정해진 규칙만 기계적으로 따르는 투자"** 라는 점이다.

이 프로젝트의 목표:

1. **수집**: 국내외의 규칙 기반(rule-based / mechanical) 투자 방법론을 폭넓게 조사한다.
2. **정형화**: 모든 전략을 동일한 스키마(상태변수/파라미터/규칙/주문유형)로 기술해
   서로 비교 가능하게 만든다 — 무한매수법의 T, VR의 V처럼.
3. **검증**: Python 백테스터로 동일 조건에서 수익률·MDD·현금비중 등을 비교한다.
4. **(후속) 실전화**: 유망 전략을 MumaeApp 엔진(Kotlin) 구조로 이식할지 판단한다.

이번 1차 범위(사용자 승인): **전략 카탈로그 + Python 백테스터 + 비교 리포트**까지.
앱 통합은 백테스트 결과를 본 뒤 별도 결정.

## 3. 전략 정형화 스키마 (StrategySpec)

모든 전략 문서는 아래 틀을 따른다. `catalog/` 폴더에 전략당 1개 md 파일.

```yaml
name:             # 전략명 (버전 포함)
origin:           # 창안자/출처, 공개 자료 링크
category:         # A~E 분류
assets:           # 대상 자산 (예: TQQQ, 주식+채권 ETF 등)
state:            # 상태변수 — 예: T(회차), V(목표가치), pool(현금)
params:           # 사용자 파라미터 — 원금, 분할수, 밴드폭, 주기, G값 등
schedule:         # 실행 주기 — 매일 / 매주 / 2주 / 월간 / 조건 발생 시
rules:            # 매수·매도·상태전이 규칙 (의사코드, 반올림 규칙 포함)
orders:           # 필요한 주문 유형 — LOC / MOC / 지정가 / 시장가
cash_profile:     # 현금 보유 특성 (평균 현금비중, 최대 투입 시점)
risk_notes:       # 하락장 거동, 강제 손절 유무, 파산 조건
automation:       # 자동화 난이도 (KIS API로 가능한가, 사람 판단 개입 지점)
backtest_notes:   # 백테스트 시 체결 가정, 데이터 요구
```

정형화 시 반올림·내림 규칙까지 명시한다 (MumaeEngine에서 배운 교훈:
반올림 규칙이 실측과 1센트라도 어긋나면 실전 검증이 무너진다).

## 4. 백테스터 설계 (Python)

위치: `new-invest-method/backtester/`

### 4.1 구조
```
backtester/
  data/           # 캐시된 일봉 CSV (커밋함 — 재현성)
  fetch_data.py   # 데이터 다운로드 (stooq/yfinance) + 캐시
  engine.py       # 일봉 루프 + 주문 체결 시뮬레이터
  broker_sim.py   # LOC/MOC/지정가 체결 규칙 (종가 기준)
  strategies/     # 전략별 구현 (Strategy 인터페이스)
  metrics.py      # CAGR, MDD, 변동성, Sharpe, 현금비중, 회전율
  report.py       # 비교표 md + 차트 PNG 생성
  tests/          # 전략 구현 vs 규칙 문서 교차검증
```

### 4.2 핵심 인터페이스
```python
class Strategy:
    def on_bar(self, state, bar, portfolio) -> list[Order]: ...
    # Order = (side, order_type[LOC|MOC|LIMIT|MKT], price, qty)
```
- 체결 시뮬: LOC 매수 = `종가 <= 지정가`면 종가 체결, LOC 매도 = `종가 >= 지정가`면
  종가 체결, MOC = 무조건 종가 체결, 지정가 = 장중 고저가 범위로 체결 판정.
- 무한매수법 구현은 **MumaeApp `MumaeEngine` 테스트 20개의 기대값과 교차검증**한다
  (같은 입력 → 같은 주문표가 나와야 함). 이것이 백테스터 자체의 정확성 검증 수단.

### 4.3 데이터
- 종목: TQQQ, SOXL, QQQ, SPY, QLD, TLT, GLD, SHY 등 (전략 커버에 필요한 만큼)
- 소스: stooq CSV(프록시 친화적) 우선, 실패 시 yfinance. 받은 CSV는 커밋해 재현성 확보.
- TQQQ 상장(2010) 이전 구간: QQQ 일수익률 ×3 − (비용·차입이자) 합성 시계열 옵션
  (2000년 닷컴버블 구간 스트레스 테스트용). 합성의 한계는 리포트에 명시.

### 4.4 비교 리포트
- 공통 조건(예: $20,000, 2010~현재 / 합성 포함 2000~현재) 아래 전략별:
  CAGR, MDD, 최악 5구간, 평균 현금비중, 매매 횟수, 세금·수수료 민감도(개략)
- 산출물: `report/comparison.md` + 차트

## 5. 파이프라인 매핑과 작업분해 (WBS)

| 단계 | 담당 | 작업 |
|------|------|------|
| 1. 페이블계획 | Fable | 본 문서 (완료) |
| 2. 솔검증 | Sonnet ×3 | ① 전략 커버리지 검증(웹서치 — 빠진 전략, 규칙 원문 접근성) ② 정형화 스키마·백테스터 설계 타당성 검증 ③ 체결 가정·데이터 계획의 함정 검증 |
| 3. 토론 | Fable + 사용자 | 검증 결과 이견 정리 → 우선 구현 전략 확정(2~4개 + 기준선), 미해결 쟁점 결정 |
| 4. 페이블오케스트 | Fable | 확정 범위를 병렬 작업으로 분해·발주·통합·품질 게이트 |
| 5. 솔구현 | Sonnet ×N | 카탈로그 문서 병렬 작성 → 데이터·엔진 → 전략 구현 → 리포트 |

## 6. 미리 식별한 쟁점 (토론 안건 후보)

1. **체결 가정의 한계**: 백테스트의 "LOC=종가 체결"은 실제 호가·유동성을 무시한다.
   TQQQ/SOXL은 유동성이 충분해 대체로 무해하지만 리포트에 가정을 명시해야 함.
2. **합성 TQQQ 사용 여부**: 2010년 이전 스트레스 구간(닷컴버블)을 보려면 합성이
   필수지만, 합성 오차(비용 추정)가 결과를 왜곡할 수 있음.
3. **변동성 돌파(C4)의 적합성**: 데이트레이딩 성격이라 "일희일비하지 않는 장기 규칙
   투자"라는 프로젝트 취지와 어긋날 수 있음 — 포함/제외 결정 필요.
4. **세금**: 해외주식 양도세 22%가 회전율 높은 전략(무매·VA)에 불리하게 작용.
   세후 비교를 1차 범위에 넣을지.
5. **우선 구현 전략 선정**: 백테스터 1차 구현은 기준선(DCA, 무매 V4.0) + 후보 몇 개로
   시작하는 것이 현실적 — 어떤 것을 먼저 할지.
