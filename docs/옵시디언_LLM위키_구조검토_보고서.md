# Obsidian LLM 위키 구조 검토 보고서

> 작성: 2026-07-07 · 분석 범위: Google Drive `000. Obsidian vault` 전체 (~235개 md 파일)
> 프로세스: Opus 에이전트 5개 병렬 raw 전수 분석 → Fable 최종 종합
> 확정 방향: 사람+LLM 겸용 / 하이브리드(폴더+태그+MOC) / 구볼트 분석 포함·이관 선별 / 보고서+실물 산출

## 1. 요약 (TL;DR)

- 볼트는 **전환기 상태**다. 구볼트(900번, ~193개)는 아카이브됐고, 신규 볼트(100번, 29개)는 뼈대만 있으며, 실제 노트는 INBOX(13개)에 쌓이고 있다.
- 전체 ~235개 md 중 **실질 지식 자산은 약 40개**. 나머지는 강의자료 6세대 버전 중복(~90개), 자소서 v1~v6 버전군(~30개), 빈 스텁, sync conflict 사본이다.
- **LLM 위키의 시도는 이미 있었다**: 구볼트에 Karpathy 패턴의 `claude-obsidian` 플러그인(hot.md → index.md → 페이지 3단 조회, entities/concepts 구조)이 설계됐으나 7개 스킬 중 1개만 구현된 채 중단됐다. 이 설계 철학은 재사용한다.
- **링크 그래프가 비어 있다**: 정제된 강의노트들이 [[AI Agent]], [[임베딩]] 등 수십 개 위키링크를 걸었지만 대응 노트가 하나도 없는 고아 링크다. 색인(MOC) 계층 신설이 핵심 과제.
- **긴급 보안 이슈 1건**: INBOX `구글 api.md`에 구글 서비스계정 private key가 평문 노출. 키 회수(rotate) 필요.
- 산출물: 본 보고서 + 볼트에 바로 넣을 수 있는 실물 파일 세트(`vault/` — INDEX.md, CLAUDE.md, MOC 6종, 템플릿 5종, 이관 체크리스트).

### 2.2 핵심 문제 5가지

1. **분류 체계 부재로 INBOX가 종착지가 됨.** 신규 볼트 골격(100 시사 / 200 업무 / 300 학습 / 998 템플릿 / 999 일상)은 좋으나, "언제 무엇을 어디로 보내는가"의 규칙이 없어 새 노트가 전부 INBOX에 정체된다. 투자·프로젝트·커리어 노트는 갈 곳 자체가 없다.

2. **링크·색인 계층이 없다.** v3 템플릿이 위키링크 슬롯을 강제하지만, 링크가 향할 개념 노트·MOC·인덱스가 존재하지 않아 링크가 전부 고아 상태. "LLM 위키"의 핵심인 그래프가 형성되지 않는다.

3. **메타데이터 3원화 + 미적용 다수.** 강의(lecture, 12키) / 클리핑(clippings, 7키) / 일반(note, 9키) 스키마가 병존하고, 구볼트·INBOX 절반은 frontmatter 자체가 없다. `type: 강의`(한글값) 같은 스키마 이탈도 있다. 단, `status: raw → draft → refined` 상태머신은 이미 잘 쓰이고 있어 **살릴 자산**이다.

4. **명명 규칙 혼재.** `260604_` 날짜 접두, `W23`/`WR26`/`W24(MR6)` 위클리 3종 3규칙, `무제` 방치, `CW.md.md` 이중 확장자, `Data/DATA` 대소문자 중복, `(conflict 2026-...)` 동기화 사본.

5. **버전 스택이 지식을 매몰시킴.** 건조과정이론 강의 V2→V3→V3.01→V3.1→V3.2→최종의 6세대 ~90파일, 자소서 v1~v6 ~30파일. 각 계열의 최종본 1개만 정본이고 나머지는 노이즈다.

## 3. 목표 아키텍처

### 3.1 설계 원칙

1. **사람 친화 폴더 + LLM 친화 메타데이터의 이원 설계** — 폴더는 얕게(사람의 탐색), frontmatter·인덱스는 엄격하게(LLM의 파싱).
2. **토큰 절약형 조회 경로** (claude-obsidian 설계 계승, 단순화): `INDEX.md`(~1k 토큰) → 도메인 `MOC`(~1k) → 개별 노트 3~5개. LLM이 볼트 전체를 읽지 않게 한다.
3. **정본(canonical) 1개 원칙** — 버전·초안은 900 아카이브로. 위키에는 최종본만.
4. **INBOX는 통과 지점** — 캡처는 자유, 단 주간 분류(triage)로 반드시 비운다.
5. **점진 구축** — 개념 노트는 미리 만들지 않고, 2개 이상의 노트가 참조할 때만 생성(고아 링크 방지).

### 3.2 폴더 구조 (볼트 루트 기준)

현재 신규 볼트가 `100. 신규 Vault` 폴더 안에 중첩되어 있는데, 이를 **볼트 루트로 승격(평탄화)** 한다:

```
000. Obsidian vault/          ← Obsidian 볼트 루트
├── INDEX.md                  ← 마스터 인덱스 (위키의 정문)
├── CLAUDE.md                 ← LLM 사용 규약 (읽기 경로·쓰기 규칙)
├── Me.md                     ← 프로필/페르소나 (LLM 컨텍스트용)
├── 000. INBOX/               ← 캡처 전용, 주간 비움
├── 100. 시사/                ← 뉴스 스크랩, 테크·산업 동향
├── 200. 업무/                ← 01.위클리 / 02.전고체 / 03.SIB / 99.특허
├── 300. 학습/                ← 01.강의 세미나 / 02.전극공정 이론 / 03.AI·PKM
├── 400. 투자/                ← 매매전략(무한매수·VR) / 개인재무
├── 500. 프로젝트/            ← 무한매수 앱 / EDS 분석툴 / AI 툴링
├── 600. 커리어/              ← 경력 마스터 / 자소서 / 프로보노
├── 700. 개념/                ← 위키 개념 노트 (고아 링크의 착지점, 점진 생성)
├── 900. 아카이브/            ← 구볼트 원본 동결 (기존 900번 그대로)
├── 998. 템플릿/
├── 999. 일상/
└── 999. 첨부파일/
```

- 기존 `.obsidian/app.json`의 "새 노트 → 000. INBOX" 설정과 그대로 호환된다.
- `100. 신규 Vault` 껍데기 폴더는 내용 승격 후 제거.

### 3.3 통합 frontmatter 스키마

기존 v3 템플릿을 최대한 계승하고 `domain` 하나만 추가한다 (기존 노트 수정 비용 최소화):

```yaml
---
type: note | lecture | clipping | weekly | project | patent | reference | concept | moc
status: raw | draft | refined        # 기존 상태머신 유지
domain: 시사 | 업무 | 학습 | 투자 | 프로젝트 | 커리어 | 일상
topic: 한 줄 주제
created: YYYY-MM-DD
modified: YYYY-MM-DD
source: 출처 (강의명/URL/회의)
related: []                          # [[링크]] 목록
tags: []
# lecture 전용 추가: course / speaker / venue
---
```

규칙: 값은 영문 소문자 enum 고정(`강의` 같은 한글 값 금지), Dataview 인라인 필드(`Term ::`)는 v3 방식 유지.

### 3.4 명명 규칙

| 유형 | 규칙 | 예 |
|---|---|---|
| 지식 노트(evergreen) | 서술형 제목, 버전 접미 금지 | `전고체 음극 바인더 마이그레이션 검토.md` |
| 이벤트성(강의·회의) | `YYMMDD_이름` | `260604_SKO_AI개론_3강.md` |
| 위클리 | `YYWnn_위클리` 단일화 | `26W23_위클리.md` |
| 금지 | `무제`, `.md.md`, `(conflict...)`, vN 버전 스택 | 버전은 900 아카이브로 |

## 4. 색인(인덱스) 설계

3단 계층. LLM과 사람이 같은 문을 쓴다.

1. **INDEX.md (마스터 인덱스, ~1k 토큰)** — 도메인별 MOC 링크 + 최근 추가/변경 5개 + 볼트 통계. 모든 세션의 진입점.
2. **MOC 6종 (도메인 지도, 각 ~1k 토큰)** — `MOC_시사`, `MOC_업무`, `MOC_학습`, `MOC_투자`, `MOC_프로젝트`, `MOC_커리어`. 도메인 내 정본 노트를 주제 묶음으로 나열하고, 미이관 구볼트 자산은 체크박스로 표기해 이관 진행판을 겸한다.
3. **개념 노트 (700. 개념/, 점진 생성)** — 강의노트들의 고아 링크([[임베딩]], [[V2G]] 등)는 **2개 이상 노트가 참조할 때만** 실제 노트로 승격. 생성 시 `type: concept`, 정의 3줄 + 역링크로 시작.

hot.md(초단기 캐시)는 도입하지 않는다 — 볼트 규모(정본 ~40개)에서는 INDEX.md가 그 역할을 겸하고, 유지 비용만 생긴다. 정본이 200개를 넘으면 그때 재검토.

## 5. LLM 활용 파이프라인

### 5.1 운영 루프 (주간)

```
캡처(수시)          분류(주 1회, LLM 보조)         활용(수시)
새 노트 → INBOX  →  frontmatter 부여·개명·이동  →  질의: INDEX → MOC → 노트
                    MOC/INDEX 갱신                  집필: 정본에 통합, status 승급
                    고아링크 점검(lint)
```

- **ingest (주간 분류)**: Claude에게 "INBOX 비우기" 요청 → 각 노트에 스키마 적용, 대상 폴더 제안, MOC에 등록. 사람은 승인만.
- **query**: CLAUDE.md의 읽기 경로 규칙 덕에 어떤 세션이든 INDEX → MOC → 노트 순으로 저토큰 조회.
- **lint (월간)**: 고아 링크, frontmatter 누락, status=raw 정체 노트, INBOX 잔류물 보고.

### 5.2 접속 방식

현재 볼트는 Google Drive 동기화 상태다. 두 가지 경로를 병행 권장:

- **단기 (현행 유지)**: Claude Code 세션 + Google Drive MCP로 직접 읽기/쓰기. 이번 분석과 동일한 방식. 설정 불요, 단 파일 단위 접근이라 대량 작업은 느림.
- **중기 (권장)**: 볼트를 git 저장소로 관리 (이 `cw` 저장소 또는 별도 repo). diff 기반 리뷰·롤백·CLAUDE.md 자동 로드·스킬 연동이 가능해져 LLM 위키 운영이 훨씬 강력해진다. Obsidian은 로컬 폴더를 그대로 쓰므로 Drive ↔ git 병행도 가능(단, .obsidian conflict 파일은 .gitignore).

구볼트의 claude-obsidian 플러그인(스킬 7종 선언)은 **비전은 계승하되 코드는 폐기**한다. 실제 필요한 것은 ingest/query/lint 3개 루틴이며, 이는 CLAUDE.md 규약만으로 어떤 Claude 세션에서도 수행 가능하다. 자동화가 필요해지면 그때 스킬로 승격.

### 5.3 Me.md의 재활용

빈 파일로 방치된 Me.md를 프로필 노트로 채우면(직무: 전고체 전극공정 R&D, 관심: 투자 자동화·AI 툴링, 문체 선호 등) 모든 LLM 세션이 이를 컨텍스트로 읽어 답변 품질이 일관되게 오른다. CLAUDE.md 읽기 경로에 포함해 두었다.

## 6. 마이그레이션 플랜 (선별 이관)

> 상세 파일별 매핑은 `vault/migration/이관_체크리스트.md` 참조.

- **Phase A — 골격 투입 (30분)**: `vault/` 산출물(INDEX, CLAUDE.md, MOC 6종, 템플릿 5종)을 볼트 루트에 복사. 신규 Vault 하위 폴더를 루트로 승격, 400/500/600/700 폴더 신설.
- **Phase B — 보안·위생 (30분)**: 구글 api 키 회수→파일 삭제, conflict 사본 삭제, 빈 파일 정리, `CW.md.md` 2주제 분할, `Migration.md` 개명.
- **Phase C — INBOX 비우기 (1시간, LLM 보조)**: 13개 노트를 체크리스트 매핑대로 frontmatter 부여 후 이동. INBOX 0개 달성.
- **Phase D — 구볼트 정예 이관 (2~3시간, LLM 보조)**: migrate=yes ~25개를 정본으로 이관(개명+frontmatter+MOC 등록). 구볼트 폴더는 `900. 아카이브`로 개명 후 동결 — **삭제하지 않는다**.
- **Phase E — 그래프 형성 (상시)**: 주간 ingest 루프 가동. 참조 2회 이상 개념부터 700번에 승격.
